# TicketSys

This is a small Java command line app for reserving tickets. I kept the data in
memory, so everything is reset when the program is stopped.

## Run it

JDK 25 and Gradle are needed. The Gradle wrapper is included, so use it from
the project root:

```bash run
./gradlew build
./gradlew run
```

To run only the automated tests:

```bash
./gradlew test
```

The test suite currently contains three test classes covering ticket
inventory, reservation state transitions, reservation expiry, atomic
reservations, and payment idempotency.

## What it does

An organiser can create an event, add ticket types, and publish it. Customers
can reserve tickets for 15 minutes and then pay for them. A reservation can
also be cancelled or allowed to expire.

The ticket counts are kept as:

```text
available = allocation - reserved - sold
```

The payment reference is used to make a repeated payment return the same order.

## Commands

```text
help
create-event <organiserId> <name> <opensAt> <closesAt> <startsAt>
add-ticket <eventId> <organiserId> <name> <price> <allocation> <perCustomerLimit>
publish <eventId> <organiserId>
list-events
show-event <eventId>
reserve <eventId> <customerId> <ticketTypeId:quantity[,ticketTypeId:quantity]>
show-reservation <reservationId>
cancel <reservationId> <customerId>
expire
pay <reservationId> <customerId> <amount> <paymentReference>
show-order <orderId>
stats
exit              (quit is also accepted)
```

Event times use hours with AM or PM, for example `10AM`, `8PM`, and `9PM`.
They are booked for today in the system's default time zone. The sales window
must satisfy `opensAt <= closesAt <= startsAt`, and the event must not already
have started when it is published or reserved. Names, ids, and payment
references are one word in the CLI. Money is entered in USD. Reservations stay
pending for 15 minutes.

The second `pay` command shows payment idempotency. The `carol` reservation is
left unpaid so it can expire after the 15-minute hold. There is no manual clock
in the app; `expire` checks the real current time. The example uses placeholder
IDs and timestamps: copy the IDs printed by your own run, and run the commands
while the event is still inside its sales window.

For multiple ticket types, separate request lines with commas:

```text
reserve <eventId> <customerId> <ticketTypeId1>:2,<ticketTypeId2>:1
```

The entire reservation is validated atomically. If any requested line fails,
none of the lines reserve seats.

## Tests

Run the complete test suite with:

```bash
./gradlew test
```

The tests are located under `src/test/java`:

- `TicketFlowBusinessCoreTest` verifies atomic reservation behavior, payment
  idempotency, expiry, seat release, and injected test time.
- `ReservationTest` verifies the 15-minute hold, totals, ownership, actionable
  state, and valid or invalid reservation transitions.
- `TicketTypeTest` verifies available-seat calculations, reserve/release/sell
  transitions, and inventory invariants.

The tests use a fixed clock instead of waiting 15 real minutes. The CLI itself
uses the real current time.

## Project folders

- `domain` contains events, tickets, reservations, orders, and money.
- `TicketFlowManager` contains the main rules for events, reservations, and payment.
- `storage` contains the in-memory repositories.
- `Cli.java` reads commands and prints results.

The tests cover ticket seat counting, reservation states, expiry, atomic
reservations, and payment idempotency.
